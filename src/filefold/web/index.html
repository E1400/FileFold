FileFold splits one large Abaqus .inp file into a small main file plus child files. The main file pulls the children back in with *INCLUDE, so Abaqus reads the model exactly as before. This page describes each function. New to it? or load a deck from Sample data on the New Workspace screen.

Creating a workspace

  1. Upload. Drop a .inp file, click to browse, or choose Sample data. Nothing is created yet.
  2. Inspect. The block inspector lists every keyword block with its line range, coloured by category. A ▸ opens the blocks nested inside a *STEP, *PART or *ASSEMBLY.
  3. Choose. Tick the categories that should get their own file, and optionally finer splits (see below). Filenames can be changed.
  4. Create workspace. The main file keeps an *INCLUDE, INPUT=file line where each extracted block used to be.

Categories

Every keyword belongs to one category. Extracting a category moves all its top-level blocks into one child file.

Geometry: *NODE, *ELEMENT, *NSET, *ELSET, *SURFACE, and *PART blocks.
Properties that link elements to materials: *SOLID SECTION, *SHELL SECTION, *BEAM SECTION, *ORIENTATION, connector sections.
*MATERIAL with all its options (*ELASTIC, *PLASTIC, *DENSITY, and so on).
Analysis steps, *STEP to *END STEP, with everything inside them (boundary conditions, loads and output requests inside a step stay in the step).
Loads and boundary conditions defined outside steps: *BOUNDARY, *CLOAD, *DLOAD, *AMPLITUDE, *TEMPERATURE.
Contact pairs, general contact and interaction properties: *CONTACT PAIR, *CONTACT, *SURFACE INTERACTION, *FRICTION.
Ties, couplings and rigid bodies: *TIE, *COUPLING, *MPC, *EQUATION, *RIGID BODY.
Starting state: *INITIAL CONDITIONS.
Output requests: *OUTPUT, *NODE OUTPUT, *ELEMENT OUTPUT, *RESTART, print and file requests.
Model set-up: *HEADING, *INCLUDE, *ASSEMBLY, *INSTANCE. This always stays in the main file and cannot be extracted.
Keywords FileFold does not recognise. They stay with the keyword above them and cannot be extracted on their own.

Going deeper

A ticked category can be split into finer files. You only see options that will really produce a file for your deck.

Nodes, elements, node sets, element sets, surfaces, or one file per part.
One file per material, each with its options.
One file per step.
Contact pairs, interaction properties, general contact.
Ties, couplings, rigid bodies, MPCs and equations.
Boundary conditions, amplitudes, applied loads, thermal.

Some options are alternatives for the same blocks, for example a whole part or just its nodes. The one you tick first wins and the other greys out; untick it to switch.

Files and statuses

A workspace has a main file (your original name), child files (one per extracted category) and sub-child files (finer splits inside a child). FileFold remembers a fingerprint of everything it wrote.

clean
The file is exactly as FileFold wrote it.
edited
The file was changed since, for example in the editor.
missing
The file is gone from the workspace.

Editing files

View / Edit opens any file. Ctrl/Cmd+S saves, Ctrl/Cmd+F finds, Ctrl/Cmd+G selects a line range, Ctrl/Cmd+/ comments or uncomments the selected lines. Leaving with unsaved changes asks whether to save, discard or keep editing. Windows and Unix line endings are kept as they were.

The Splits tab

Change how a workspace is split at any time: extract more categories, split further, fold files back into their parent by unticking them, or rename files. Lines are never lost or duplicated, so the pieces always add up to the original model.

Reimporting a new version

When the original model changes, Re-import the new file. Each existing child is compared with the new version:

safe to update
Changed upstream, not edited here. Updated by default.
unchanged
Same in both. Left alone.
conflict
Changed upstream and edited here. You choose whether to overwrite your edits.

Categories that are new in the file can be extracted at the same time.

Export and command line

Export ZIP downloads the main file and every child. Everything the app does is also available as filefold commands (inspect, split-partial, workspace create, extract, resplit, recombine, reimport, export), and workspaces are shared with the app. Your files are kept in this browser, on this device; nothing is uploaded anywhere. Decks up to 100 MB are tested here; use the desktop app or command line for larger ones. on the server, in this app's workspace folder.

How the parser reads your file

  • Lines. A line starting with * is a keyword, ** is a comment, anything else is data. Blank lines, comments and data stay with the keyword above them.
  • Wrapped keyword lines. A keyword line ending in a comma continues on the next line; its parameters are merged. Quoted parameters may contain commas.
  • Options stay with their parent. *ELASTIC follows its *MATERIAL, *FRICTION its *SURFACE INTERACTION. A keyword FileFold does not know is kept with the block above it, so a split can never separate them.
  • Containers. *STEP, *PART, *ASSEMBLY and *INSTANCE own the blocks inside them, which move with the container.
  • Keyword coverage. Every keyword in the Abaqus 2016 Keywords Reference is recognised and assigned a category.
  • Byte-exact. Reassembling the pieces reproduces your original model exactly: same lines, same line endings.
  • Limits. An *INCLUDE that is already in your file is kept as written; its target file is not opened.
